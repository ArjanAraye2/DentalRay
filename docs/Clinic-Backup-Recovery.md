# DentalRay Clinic Backup and Recovery

این سند حداقل رویهٔ قابل‌قبول برای پشتیبان‌گیری و بازیابی DentalRay در مطب
را تعریف می‌کند. هدف اصلی این است که دیتابیس، تصاویر و تنظیمات متعلق به یک
لحظه باشند و نسخهٔ پشتیبان ناقص، سالم تلقی نشود.

## اجزای الزامی هر Backup

هر مجموعهٔ پشتیبان باید این سه جزء را کنار هم نگه دارد:

1. فایل Full Backup دیتابیس `DentalRay` با پسوند `.bak`؛
2. کپی کامل مسیر `RadiologyStorage:RootPath` که معمولاً
   `D:\RadiologyData` است؛
3. فایل تنظیمات
   `C:\ProgramData\DentalRay\DentalRay.config.json`.

نام پوشهٔ مجموعه باید زمان محلی را بدون نویسهٔ مبهم ثبت کند؛ برای مثال:

```text
DentalRay-Backup-2026-09-16-1238
├── Database\DentalRay.bak
├── RadiologyData\...
├── Configuration\DentalRay.config.json
└── manifest.txt
```

## ترتیب صحیح Backup

برای ایجاد یک Snapshot هماهنگ، مراحل باید دقیقاً به این ترتیب اجرا شوند:

1. مقصد Backup روی دیسکی غیر از دیسک اصلی اطلاعات انتخاب شود.
2. فضای آزاد مقصد کنترل شود.
3. سرویس `DentalRay` متوقف شود؛ اگر توقف ناموفق بود عملیات لغو شود.
4. از دیتابیس Full Backup با گزینه‌های `COPY_ONLY`، `CHECKSUM` و
   `COMPRESSION` گرفته شود.
5. دستور `RESTORE VERIFYONLY ... WITH CHECKSUM` روی فایل `.bak` موفق شود.
6. تمام محتوای مسیر `RadiologyStorage:RootPath` کپی شود.
7. فایل `DentalRay.config.json` کپی شود.
8. تعداد و مجموع اندازهٔ فایل‌های تصاویر مبدأ و مقصد در `manifest.txt`
   ثبت و مقایسه شود.
9. فقط پس از موفقیت همهٔ مراحل، مجموعه با وضعیت `Complete` علامت‌گذاری شود.
10. سرویس `DentalRay` در بخش `finally` دوباره Start شود؛ شکست Backup نباید
    سرویس مطب را خاموش باقی بگذارد.

Backup ناقص نباید وارد چرخهٔ نگهداری شود و نباید نسخهٔ سالم قبلی را حذف کند.

## سیاست نگهداری و کنترل فضا

برای جلوگیری از پرشدن دیسک:

- هفت Backup روزانهٔ کامل نگهداری شود؛
- چهار Backup هفتگی نگهداری شود؛
- حذف نسخه‌های قدیمی فقط پس از موفقیت و Verify شدن Backup جدید انجام شود؛
- اگر پس از Backup کمتر از 20 درصد فضای مقصد آزاد می‌ماند، عملیات قبل از
  کپی تصاویر متوقف و به مدیر هشدار داده شود؛
- مقصد نباید داخل `D:\RadiologyData` یا یکی از زیرپوشه‌های آن باشد.

## آزمون بازیابی

حداقل ماهی یک بار، بازیابی آزمایشی روی سیستم یا Instance جدا انجام شود:

1. سرویس DentalRay متوقف شود.
2. فایل `.bak` روی دیتابیس آزمایشی Restore شود.
3. پوشهٔ تصاویر در یک مسیر آزمایشی کپی شود.
4. یک Configuration آزمایشی با همان دیتابیس و مسیر تصاویر ساخته شود.
5. ورود مدیر، جست‌وجوی بیمار، بازکردن Study و نمایش چند تصویر آزمون شود.
6. نتیجه، تاریخ، نام Backup و نام آزمون‌کننده ثبت شود.

## ترتیب بازیابی اضطراری در مطب

1. سرویس `DentalRay` متوقف شود.
2. از وضعیت خراب فعلی یک کپی جدا تهیه شود؛ روی آن نوشته نشود.
3. آخرین مجموعهٔ دارای وضعیت `Complete` انتخاب شود.
4. دیتابیس `DentalRay` از فایل `.bak` بازیابی شود.
5. تصاویر به مسیر ثبت‌شده در Configuration برگردانده شوند.
6. فایل Configuration بازیابی و مجوز آن فقط برای `SYSTEM` و
   `Administrators` تنظیم شود.
7. مجوز پوشهٔ تصاویر به‌صورت بازگشتی فقط برای `SYSTEM` و
   `Administrators` تنظیم شود.
8. سرویس Start و سناریوهای ورود، بیمار، Study و تصویر بررسی شوند.

## معیار تکمیل قابلیت خودکار

پیاده‌سازی خودکار آینده فقط زمانی کامل محسوب می‌شود که:

- بدون ذخیرهٔ رمز SQL کار کند و Configuration موجود را بخواند؛
- Admin-only باشد و همهٔ عملیات را Audit کند؛
- در هر خطا سرویس را دوباره Start کند؛
- Backup دیتابیس را Verify کند؛
- Backup ناقص را Complete اعلام نکند؛
- سیاست نگهداری را فقط پس از موفقیت نسخهٔ جدید اعمال کند؛
- گزارش قابل‌فهم فارسی از مسیر، زمان، اندازه و خطا ارائه دهد.
