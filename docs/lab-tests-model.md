# مدلِ «آزمایشات» در رسیرا

ثبت‌شده: ۱۴۰۵/۰۷/۱۰ — طبقِ توضیحِ مستقیمِ کاربر.

## اصل
آزمایش **مثلِ تصویرِ رادیولوژی** است: یک «سندِ» پیوست‌شده به مراجعه که پزشک
در صورتِ نیاز می‌بیندش. نه اقدام است، نه مالی، و **هیچ ارتباطی بینِ آزمایش و
اقدام نیست** — پزشک با دانش/تجربه/معاینه/گفت‌وگو با بیمار، مستقل اقدام می‌کند.

```
مراجعه (Study)
├── اقدامات (tblStudyActions)      ← تصمیمِ مستقلِ پزشک؛ مالی (مبلغ/تخفیف)
├── تصاویرِ رادیولوژی              ← سندِ پیوست‌شده
└── آزمایشات (گزارشِ آزمایشگاه)    ← سندِ پیوست‌شده؛ «ابزارِ پزشک برایِ اقدام»
     ├── نامِ آزمایشگاه، تاریخ
     ├── یک یا چند صفحه/تصویر که «یکجا» استخراج می‌شوند
     └── فیلدهای استخراج‌شده (هموگلوبین و …) = زاییدهٔ خودِ آزمایش
```

## قواعد
- **هر گزارشِ آزمایشگاه = یک «آزمایش»** (یک یا چند صفحه). صفحه‌هایِ یک گزارش
  **یکجا** استخراج می‌شوند (یک batch).
- **آزمایش مبلغ ندارد** و واردِ بخشِ مالی نمی‌شود.
- **فیلدهای استخراج‌شده متعلق به خودِ آزمایش‌اند** ⇒ اگر یک فاکتور در دو آزمایشِ
  یک مراجعه اندازه‌گیری شود، دو مقدارِ مستقل می‌ماند (هرکدام با سندِ خودش).
- **یک مراجعه می‌تواند چند آزمایش داشته باشد** — الگویِ «یک مراجعه برایِ هر
  گزارش» کنار گذاشته شد (بعدها مشکل‌ساز می‌شد).

## نگاشت به داده‌ها (بدونِ جدولِ جدید)
| مفهوم | محلِ ذخیره |
|---|---|
| آزمایش (سند: نامِ آزمایشگاه، تاریخ، صفحات) | `tblLabReportExtractions` (هر batch = یک آزمایش؛ `LabName`، `SampleDate`، `ImagePath` با جداکنندهٔ `\|`) |
| فیلدهای استخراج‌شده | `RawJson` همان batch (فهرستِ `LabSheetParser.Row`: نام/مقدار/واحد/بازه/بخش/ضریبِ اطمینان) |
| مقادیرِ تأییدشده | `tblStudyFactorValues` با `ExtractionID` ← به همان آزمایش وصل است |
| دیکشنریِ تست‌ها | `tblClinicalFactors` |
| اقدامات (جدا و مستقل) | `tblStudyActions` — هیچ ستونِ ارتباطی با آزمایش ندارد |

## UI
- پنلِ **«آزمایشات این مراجعه»** — هم‌سطحِ «اقدامات این مراجعه»، درست کنارِ
  تصاویر (`study-lab-tests.js`).
- کارتِ هر آزمایش: نامِ آزمایشگاه · تاریخ · تعدادِ صفحات · تعدادِ فیلدها.
- جدولِ فیلدها: نام / مقدار / واحد / **بازهٔ چاپ‌شده** / وضعیت (در بازه، بالاتر،
  پایین‌تر) / ضریبِ اطمینان. کلیک روی هر ردیف ← **تکهٔ خودِ برگه** (crop) برایِ
  راستی‌آزمایی.
- endpoint: `GET /api/ai/images/lab-tests?studyID=`

## چرا این مدل؟
- «یک مراجعه برایِ هر گزارش» ⟹ هر آزمایشِ تکرارشده در دو مراجعه، پرونده را
  تکه‌تکه می‌کرد.
- «آزمایش = اقدام» ⟹ اشتباه بود؛ آزمایش مالی نیست و تصمیمِ پزشک نیست.
- «آزمایش زیرمجموعهٔ اقدام» ⟹ اشتباه بود؛ آزمایش هم‌سطحِ اقدام، زیرمجموعهٔ
  مراجعه است.
